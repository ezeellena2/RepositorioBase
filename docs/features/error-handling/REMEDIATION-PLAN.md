# Error handling — remediation plan

Proposed 2026-09-10. Implements [error-handling-standards](../../../.agents/skills/error-handling-standards/SKILL.md) and its [rules](../../../.agents/skills/error-handling-standards/references/error-handling-rules.md) across the whole system.

Source: a read-only audit of six layers, each checked by an adversarial verifier that tried to refute every
finding — 61 confirmed (0 critical, 13 high, 25 medium, 23 low), 2 refuted.
Every item links to its findings in [AUDIT-FINDINGS.md](AUDIT-FINDINGS.md), which carries the `file:line`
evidence. Do not re-audit; re-verify only what you touch, because the code may have moved since.

## How to work this plan

- Work the items in order: every P0, then P1, P2, P3. Tick an item's box only when it is implemented, tested and
  verified.
- Each item follows the skill: the discriminating test first (RED), the smallest change (GREEN), then refactor.
  Tests assert the exact status, `code`, `errors` keys and wording — a test that only sees "an alert" proves
  nothing.
- Priorities: **P0** user-visible breakage or a security/leak risk · **P1** missing coverage on core flows
  (B2B/B2C registration, sign-in) · **P2** consistency · **P3** polish.

## Cross-cutting cautions

1. **Enumeration safety outranks helpfulness.** Neutral public flows never distinguish account or token state.
   An input-only field error is allowed on them only when it passes the skill's three-part test, and a parity
   test (taken vs free address, live vs dead token) proves the bodies are identical apart from `traceId`.
2. **SPEC amendments.** Some items change behaviour a SPEC section 6 row pins — today the rows for
   `POST /api/identity/organizations/register` and `POST /api/identity/personal/register`, which answer malformed
   input with `invalid_registration`. Amend the row in the same change that ships the new behaviour. A SPEC change
   is not approved by being written: the owner states which amendments are authorized.
3. **The CUIT check digit has two paths.** `NormalizedCuit.From` is also the EF read converter
   (`OrganizationProfileConfiguration.cs:16`, `PendingRegistrationIntentConfiguration.cs:38`). Enforce the
   modulo-11 digit where a value enters the system, add a non-validating `FromStored` read path so older rows stay
   readable, and in the same change migrate fixtures (`30-12345678-9` fails the check digit, `30-12345678-1`
   passes) and make the test CUIT generator compute the digit.
4. **Logging never carries `Exception.Message`**, `ToString()`, payloads or personal data (IA-REQ-029).
