## How to read the Evidence column

The column distinguishes scoped evidence from gaps found by source inspection:

- **Covered** — named tests exercise the listed cases. This is not a claim that every requirement edge case
  was tested or that the complete suite was rerun during this review.
- **Partial** — some of it is named here and the rest is stated as a gap, in the same cell.
- **Not covered** — nothing in the suite demonstrates it.

`Covered` is evidence, not approval. Historical run statements below remain scoped to their named tests and
task records; current test execution is recorded separately in the direct review. Normative owners are unchanged,
and IA-009 supplies acceptance evidence without becoming a normative owner.

## Closure controls and their validity

- **Run records under `artifacts/`.** `artifacts/` is gitignored, so any `.trx` cited from it is a record of one
  machine's run and is not reproducible from a fresh checkout. Where one was the only citation it has been
  replaced above by the test names, which are. Nothing in this document should cite a path under `artifacts/` as
  its evidence again.
- **The commands that reproduce everything cited here** are the ones in
  [RUNNING-LOCALLY.md](RUNNING-LOCALLY.md#running-the-checks). The acceptance suite needs Docker and starts the
  whole application, including the frontend.
- **What this reconciliation did not do.** It did not complete task exit criteria, issue a workflow receipt,
  change task states or move normative owners. The direct review and scoped test run are separate evidence;
  `Partial` rows retain useful tests while naming missing coverage or an actual implementation defect.
